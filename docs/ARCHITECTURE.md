# SunfoodApp Architecture Guide

## Goals
- Разделить слой запуска приложения (`app`) от бизнес-фич (`features`) и общих утилит (`shared`).
- Явно описать провайдеры, маршруты и навигацию, чтобы избежать «божественных» компонентов.
- Подготовить почву для модульного тестирования и изолированного развития мобильной и админ-версий.

## Клиентское приложение (`src`)

```
src/
  app/
    providers/      # Глобальные провайдеры (Auth, Cart, Router и т.д.)
    navigation/     # Композиция навигационных элементов и конфигов
    routes/         # Декларации маршрутов и guard-компоненты
    index.tsx       # Точка входа для инициализации приложения
  features/         # Бизнес-фичи (например, меню, бонусы, заказы)
  entities/         # Состояния сущностей (cart, user, order) + контексты
  shared/           # Переиспользуемые элементы (ui, libs, utils)
```

### Ближайшие изменения
- Вынести обёртки и маршруты из `App.tsx` в `app/providers` и `app/routes`.
- Разложить навигацию (нижнее меню) в `app/navigation`.
- Оставить `App.tsx` минимальным: подключение провайдеров, маршрутов и корневого layout.

## Админка (`admin/src`)

Аналогичный подход:

```
admin/src/
  app/
    providers/
    routes/
    layout/
```

Дальше — постепенный перенос страниц в модули (`features/orders`, `features/promotions`) с общими компонентами в `shared`.

## Следующие этапы
1. Создать общие пакеты (`packages/shared`) для дублирующихся типов и утилит.
2. Перейти на декларативные маршруты (React Router v6) и централизованную асинхронность (TanStack Query).
3. Навести порядок в сервисах API, выделив единую точку входа и разделив Firebase/Express обязанности.
4. Внедрить CI-пайплайн (lint, typecheck, build) и подготовить автотесты после архитектурного рефакторинга.
